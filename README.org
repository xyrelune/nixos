Hello! This is my [[https://nixos.org/][NixOS]] configuration that I use to maintain my machines. 

The machines:
- ~lenovo~
- ~server~

I use [[https://orgmode.org/][org-mode]] in [[https://www.gnu.org/software//emacs/][emacs]] to manage my NixOS configuration.

To use this repo:
- First clone the repo
- Assuming you've emacs installed in your nixos system, run the command below
#+begin_src bash :tangle no
   emacs README.org --batch -f org-babel-tangle
#+end_src
   The above will generate all the .nix files.
- Then run the nixos-rebuild command
#+begin_src bash :tangle no
   sudo nixos-rebuild switch --flake .#<lenovo/server>
#+end_src
- For [[https://github.com/nix-community/home-manager][Home-Manager]] configuration, run the following while being in the repo directory.
#+begin_src bash :tangle no
   home-manager switch --flake .#kin-lenovo
#+end_src
   I only have one home-manager user configured, and that is for my ~lenovo~ machine.
- For ~server~ deployments, use the following command to do remote rebuilds
#+begin_src bash :tangle no
    nixos-rebuild switch --flake .#server --target-host kin@server.lan --build-host kin@server.lan --sudo --ask-sudo-password
#+end_src
  I am using my server as an example, ~server.lan~ is the local hostname assigned to it.
  | --target-host       | user@hostname              |
  | --build-host        | user@hostname or localhost |
  | --sudo              | running as root            |
  | --ask-sudo-password | self-explanatory           |

* The Flake File
In NixOS flakes are used to package and manage Nix projects, flakes are used as a way to produce reproducible builds as well as controlling multiple systems.

I also use flakes as a way to import my non-flake files and use it to import files within the various non-flake git repositories, example of this last statment is the input named ~walls~ that fetches from [[https://codeberg.org/kinest/walls][my repo]] that stores wallpapers, this is later used in [[modules/features/wm/niri.nix#L218][Niri]] along with [[https://swaybg.com/][Swaybg]].

#+begin_src bash

| -w     | overwrite            |

| --V0   | Convert to mp3 V0    |
| --FLAC | Convert to flac      |

~[10de:2560]~ and ~[10de:228e]~ is of importance.

During VM Creation, do the following steps:
- Create 2 new disks
  - A VirtIO disk with ~Cache mode~ set to ~none~ and ~Discard mode~ set to ~unmap~.
- Add the gpu pci ids, usb hosts etc to be passed through with ~Add hardware~.
- Edit the xml file of the vm to have the following
  #+begin_src xml
    <memballon model="none"/>
  #+end_src
  
Note: Virtio drivers never worked well for me so I just install ~spice-guest-tools~ on the windows vm.

Make sure looking glass client on the host machine matches the version that we install on the windows vm.
To check:
#+begin_src bash
  nix-instantiate --eval -E "(import <nixpkgs> {}).looking-glass-client.version"
#+end_src
After installing the virtual machine and installing the matching looking glass host, run this in an admin powershell.
#+begin_src powershell
  SCHTASKS /Create /TN "Looking Glass" /SC  ONLOGON /RL HIGHEST /TR 'C:\Program Files\Looking Glass (host)\looking-glass-host.exe'
#+end_src
After that run this in an admin cmd:
#+begin_src bat
  C:\Program Files\Looking Glass (host)\looking-glass-host.exe InstallService
#+end_src
Note: If the looking glass host running on a windows vm doesn't run as admin, then any applications invoking admin requests or just running as admin won't be visible to us on our looking glass client screen. So make sure to run the above command in an admin cmd prompt window.

Back on the vm xml file add the following snippet for looking glass to work.
#+begin_src xml
  <shmem name="looking-glass">
    <model type="ivshmem-plain"/>
    <size unit="M">32</size>
    <address type="pci" domain="0x0000" bus="0x0b" slot="0x01" function="0x0"/>
  </shmem>
#+end_src
Change video mode to none under devices.
#+begin_src xml
  <video>
    <model type="none"/>
  </video>
#+end_src
Remove tablet input under devices.
To remove the topoext error, which looking glass throws add the below feature.
#+begin_src xml
  <cpu mode="host-passthrough" check="none">
    <feature policy="require" name="topoext"/>
  </cpu>
